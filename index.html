Project Evolution & Objective

Our first prototype used a baseband optical link with a 1W visible LED emitter and an Op-Amp receiver stage. In controlled darkness, the signal was usable, but real deployment quickly failed due to ambient sunlight and room lighting noise. The final architecture pivots to a modulated physical layer using a 940nm IR LED and a precisely generated 38kHz carrier, which allows narrowband reception and high rejection of environmental interference.

Prototype A: Baseband Path

Direct optical intensity modulation, visible emitter, and analog gain path. High susceptibility to DC and low-frequency optical noise.

Production Design: Modulated IR

940nm source, carrier-gated OOK, demodulating receiver front-end, and deterministic digital decoding at the MCU boundary.

System Architecture: Pipeline Walkthrough

Signal flow from keypad event to optical transport, demodulation, decryption, and OLED rendering.

1

Data Generation

4x4 matrix keypad scanned via GPIO polling with software debouncing and key-release gating.

2

Baseband Framing

ATmega328P serializes each key into UART framing logic at 9600 baud architecture target.

3

Modulation

On-Off Keying at hardware level where baseband controls visibility of the 38kHz carrier.

4

Physical Channel

Free-space propagation using 940nm IR photons between isolated transmitter and receiver nodes.

5

Demodulation

TSOP1838 performs bandpass filtering and envelope extraction to rebuild clean baseband UART edges.

6

Display

Receiving ATmega328P decodes payload and updates a 0.91 inch SSD1306 OLED over I2C.

Firmware snapshot in this repository is configured at 2400 baud for bench stability during hardware validation.

Deep Dive: Transmitter & OOK Modulation

The Double Inversion Trick

Native UART TX idles HIGH. Driving an IR emitter directly from an idle-high stream creates continuous optical output, overheating the LED and collapsing TSOP AGC behavior. A 74HC04 inverts UART so idle becomes LOW, yielding a dark idle state, lower thermal stress, and stable receive sensitivity.

Carrier Synthesis in Hardware

An external 16MHz crystal clocks Timer2 in CTC mode. The carrier follows f_carrier = f_clock / (2 * N * (1 + OCR2A)). With N = 1 and OCR2A = 209, hardware generates approximately 38.095kHz with zero runtime CPU modulation overhead.

74HC08 AND Gate: Hardware OOK Multiplication

The inverted UART data line and the 38kHz square-wave carrier are AND-combined by 74HC08 logic. Logic 1 in data passes the carrier burst, logic 0 suppresses it, implementing amplitude-shift OOK with deterministic timing.

Deep Dive: Receiver & Demodulation

TSOP1838 is not a raw photodiode; it is an integrated physical-layer demodulator that outputs digital baseband-compatible logic. Internally, the chain is: optical daylight filtering, transimpedance amplification, AGC control, active 38kHz bandpass filtering, envelope detection, and Schmitt-trigger squaring. This rejects 0Hz sunlight and 50/100Hz room-light artifacts before the MCU RX stage.

Optical Filter Transimpedance Amp AGC 38kHz Bandpass Envelope Detector Schmitt Trigger

The module outputs clean baseband UART directly to ATmega328P RX, minimizing software-side recovery complexity.

Deep Dive: Hardware-Level XOR Encryption

Free-space optical links can still be intercepted line-of-sight, so a lightweight symmetric cipher was added. On 8-bit AVR constraints, AES is computationally expensive and unnecessary for this threat model. XOR encryption is a single-cycle operation using eor, giving near-zero overhead.

Plaintext ⊕ SecretKey (0x5A) = Ciphertext

Transmitter: USART_TRANSMIT_SECURE (from main.asm)

; --- NEW: Encryption Subroutine ---
USART_TRANSMIT_SECURE:
    push  r17
    ldi   r17, SECRET_KEY           ; Load the secret key
    eor   r16, r17                  ; Encrypt the character in r16
    rcall USART_TRANSMIT            ; Send the garbled byte over IR
    eor   r16, r17                  ; Restore r16 to its original value just in case
    pop   r17
    ret

Receiver: Decryption Block in MAIN_LOOP (from main.asm)

MAIN_LOOP:
    lds   r16, UCSR0A
    sbrs  r16, RXC0                 ; Wait for data from the VS1838B
    rjmp  MAIN_LOOP

    lds   r16, UDR0                 ; Grab the received encrypted byte

    ; --- NEW: DECRYPTION STAGE ---
    push  r17
    ldi   r17, SECRET_KEY           ; Load the secret key
    eor   r16, r17                  ; Un-garble it back into readable ASCII!
    pop   r17
    ; -----------------------------
